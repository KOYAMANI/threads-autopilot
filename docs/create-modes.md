# 投稿作成の入力モード（2026-09-07）

| モード | 投稿の参考 | 内容の根拠 |
|---|---|---|
| 型を参考に作る | 自分の投稿を最大3本、または他人の投稿をツリー全体で貼付 | 選択したYouTube・記事・テキスト・ファイルと指示 |
| リライト | 自分の投稿1本と本人の続き、または他人のツリー全文貼り付け | 元投稿の内容。追加の参考情報・指示も入力可能 |

型を参考に作る場合は構成・語気・改行・情報の出し分けを分析し、参考投稿の内容を新素材として流用しない。リライトは選択または貼付した投稿の内容を根拠にする。YouTubeや記事は情報として使用し、書き方の見本にしない。選択した自分の投稿は最初の1本を主な型にする。

自分の投稿一覧は表示回数順の上位5件から始め、検索・並べ替え・前後5件のページ送りを使用する。参考投稿を選ばない場合の暗黙の上位3本流用は、作る画面では廃止した。

## 生成と修正

1. 資料の役割とツリー全体を分析する。
2. 原型を活かす／判断基準を示す／短く端的にする等、異なる編集方針を設計する。
3. 案ごとに固定する骨組みと、書き換える文章部分を定義する。順位、項目、固有名詞、評価ラベルなどは骨組みに保持する。
4. 各案の文章部分を別リクエストで生成して、骨組みに挿入する。
5. 項目、投稿数、文字数、設定違反、候補の重複を検査する。形式・検査で失敗した候補は最大1回修復し、まだ不適合なら成功として返さない。

通常は構成分析1回と候補生成3回。分析修復を含めて最大8回。各呼び出しの自動通信リトライは作成経路では無効。429は余分な再試行をせず利用制限を案内する。

「指示で直す」には生成時の入力を保持し、サーバーで所有者を確認して元の資料を再取得する。候補を切り替えても手修正を保持する。元の資料の取得は同一ユーザー・同一アカウントに限定する。

## UI

PCでは最大1440px、サイドナビゲーションと素材／候補の2列表示。スマホは1列。空の続き欄は必要なときに追加する。

## 制限と確認状況

- 貼り付け投稿は20,000文字。取得する本人のツリーは1本20,000文字・合計40,000文字を超える場合、黙って切らずエラーにする。
- 参考情報は各3,000文字・合計9,000文字。省略が発生した場合は画面に案内する。
- 投稿は本文＋本人の続き3件まで。参考のツリー全体を入力に使うことと、生成できる投稿数の上限は別。
- この変更は「作る」画面の手動生成。オートパイロットの既存の生成経路は別。
- 自動検査は意味の完全な保持や事実性を保証しない。動画内の情報は本文文字列との照合ができない。機能説明・語気・鮮度は公開前に確認する。
- 型チェック、既存を含む495テスト、Webビルド、本番モック除去チェックが通過。実ブラウザでPC・スマホ、5件表示、モード切替、候補切替時の編集保持、修正コンテキストを確認。生成・修正の画面操作は固定応答で検証。
- 会話内の原文と検証素材を使った実Gemini比較で旧方式の欠落や過剰な文体変化を確認して修正したが、最終版の追加品質確認はHTTP 429により未完了。
- 保存済みの投稿をGeminiへ送る実アカウントテストは自動承認レビューにより却下。保存済み投稿は外部送信していない。本人アカウントの画面はローカルでのみ確認し、投稿・予約・メール送信は行っていない。
