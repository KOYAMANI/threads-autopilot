# 投稿操作の分離とステージング招待（2026-09-08）

## 反映内容

投稿作成の操作を「下書き保存」「予約・キューに追加」「今すぐ投稿」の3つに分離した。予約シートは次の空き枠と日時指定のみ。即時投稿はCreateとQueueで共通確認画面を使い、対象アカウントと全ツリー本文を表示する。

環境判定失敗・未確定、Threads未連携、処理中は確定できない。ステージングは確認画面を表示できるが、実投稿確定は無効。サーバーの投稿・メール停止設定は維持した。

- 実ステージングのChrome Canaryで3ボタン、対象アカウントと本文の確認画面、即時投稿確定disabled、予約2選択肢を確認。保存・予約・実投稿は実行せず、確認本文を消去した。

## 招待

ユーザー指定の4人分をステージング管理APIで発行。D1読み取りで対象メモのライセンスがunused 4件であることを確認した。秘密キーはリポジトリ外の本人専用ファイル（権限0600）に保存。キー文字列をこの文書・Git・監査ログへ入れない。

登録URL: https://threads-autopilot-staging.yama-threads-apps.workers.dev/login?mode=register

1人につきキー1つ。各自のメールアドレスと8文字以上のパスワードで登録する。Threadsアクセストークンとは別物。

現ステージングのThreads接続は @yama_threads.sub の数値IDに固定されている。各人が自分のThreadsを接続するにはMeta開発モードのテスター招待・承諾と、アプリ側の許可対象拡張が別途必要。4人のユーザー名は確認待ち。全員に既存所有者アカウントやトークンを共有しない。

ステージングは実投稿・メール送信を停止しており、パスワード再設定メールも送信されない。Cronは監視専用で自動投稿は実行しない。
