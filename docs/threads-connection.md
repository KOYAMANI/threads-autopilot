# Threads接続・同期

## 2026-09-07 修正

本番アカウントの診断はAPIを読み取るだけで、結果を分析用DBに保存していなかった。接続はfull_syncを台帳に置くだけでCronの起動を待っており、初回のフォロワー・表示回数も別の日次処理に依存していた。

接続/手動同期時にfull_sync・followers・daily_views・clicksを投入し、Cloudflare Queuesに即時送信する。最初の投稿ページから投稿別の分析を開始し、全履歴の取得が終わると追加分も分析する。無料枠は25投稿単位で中断・再開し、正常な中断は新しいキューメッセージで続行する（失敗リトライの上限と分離）。Queue送信失敗時はD1の台帳に残し、Cronから回復できる。失敗を100%完了と表示しない。ホームに同期状態・保存件数・再同期ボタンを設け、分析を更新する。

プロフィールは同期時にも更新し、上部・サイドバー・設定・アカウント切替で実画像を使う。画像ロード失敗時は頭文字に戻す。

スキル参照先: `/Users/yutaro/Projects/myCompany/.claude/skills/threads-auth/scripts/oauth-token.js`。現存フォルダにSKILL.mdはなく、実行スクリプトを読んで対応した。スクリプトはOAuth認可、コード交換、長期化、保存、期限前の延長を担当する。既存長期トークンは接続時に延長を試して認識する。延長できない場合は有効期限を未確認とし、60日あると断定しない。設定から手動延長を試すこともできる。

## OAuth（トークンの手作業取得をなくす）

1. 運営者がMetaのThreadsユースケースを持つアプリを設定する。
2. OAuthの戻り先を登録する: `https://threads-autopilot.yama-threads-apps.workers.dev/api/threads/oauth/callback`
3. Cloudflare Workerに `THREADS_APP_ID` と `THREADS_APP_SECRET` を設定する。Secretはwrangler secret putで登録し、公開コードやフロントへ入れない。
4. 生徒はアプリへメールでログインし、「Threadsで接続する」を押してMeta画面で許可する。アプリ自身へのメールログインとThreadsの接続は別のもの。
5. 一般ユーザーへの公開前に、Meta側で必要な権限・公開条件・審査を確認する。開発中のアプリではロールを持つ利用者でテストする。

要求権限は threads_basic / threads_content_publish / threads_manage_insights / threads_read_replies / threads_manage_replies。実際の投稿・分析はOAuth後もThreads APIで行う。Threadsのパスワードはアプリに入力しない。

アプリIDとSecretの両方が設定されていない場合はOAuthボタンを無効にし、既存のトークン接続を残す。本番のMeta設定・実認可が完了したとは扱わない。

## OAuthの検証

状態はランダム生成し、ハッシュをD1に10分間だけ保存。開始ユーザー・セッション・HttpOnlyブラウザCookieに紐付け、一度だけ消費する。コールバックはCSP nonceとno-store/no-referrer付きの同一オリジン完了ページを介し、アプリのSameSite=Strict Cookieを維持する。認証コード・Token・App SecretをAPI応答やエラーログに返さない。

## 制約

初回の履歴取り込みには数分かかる。過去のフォロワー推移を遡って生成はできないため、接続後の観測を蓄積する。投稿取り込み上限は親投稿1500件、返信1500件。初回の投稿別分析は取得できた投稿の過去90日分を50件ずつ継続取得する。Metaの権限/レート制限による未取得は成功扱いにしない。
